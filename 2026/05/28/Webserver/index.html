Webserver

感觉在当前在IOT的漏洞挖掘中，基本是对httpd等webserver进行挖掘，然后在逆向时，对于其中的很多不太懂，逆向过程会很慢，所以先学习一下webserver。

（以某个真实的Iot设备为例）

webserver

大多数Iot设备都会内置Web Server以提供web服务（也有例外）

webserver核心：在设备或主机上的网络服务程序。

负责：

  • 监听 HTTP/HTTPS 端口
  • 接收浏览器或客户端的请求
  • 按 URL/参数把请求分发给对应处理逻辑
  • 生成并返回响应

这样就很清晰为什么Iot设备可以在Webserver里找洞了，因为它对与用户传入的HTTP请求有进行解析与处理，所以我们对其中的请求进行更改，或特定设置时，在webserver存在不安全设置时就容易产生漏洞

组成

典型的Webserver可以分为8块

1.监听层

  • socket()

  • bind()

  • listen()

  • accept()

作用：把网络连接收进来。

2.协议解析层

  • 解析 HTTP 请求行
  • 解析 Header
  • 解析 Query String
  • 解析 POST Body
  • 解析 Cookie / Session / Content-Type

作用：把原始字节流变成程序能理解的“请求对象”。

3.路由层

  • 看 URL 是什么
  • 看 Method 是 GET/POST/PUT/…
  • 决定进入哪个 handler

作用：把“请求”映射到“处理函数”。

4.认证授权层

  • 你是不是已登录
  • 你有没有权限访问这个 URL
  • 是否需要 Basic Auth / Session / Token

5.业务处理层

  • 真正干活的函数
  • 读配置、改配置、查状态、上传文件、重启服务之类

6.后端资源层

  • 文件系统
  • CGI
  • 数据库
  • 配置系统
  • NVRAM / flash / 守护进程

7.响应生成层

  • 返回 HTML / JSON / 文件 / 错误码
  • 组装 200/302/403/404/500

8.事件循环/并发模型

  • 单进程单线程事件驱动
  • 多进程
  • 多线程
  • worker 池
