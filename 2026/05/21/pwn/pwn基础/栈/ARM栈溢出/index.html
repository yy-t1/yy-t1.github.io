ARM栈溢出

由于低能耗和高性能的特点，ARM架构在移动设备和各种IOT物联网固件设备占主导地位。

ARM架构也支持大小端序，并分为32位和64位，这里以32位为例：

基础

ARM通用寄存器

32位ARM拥有16个可见的通用寄存器（R0-R15），以及一个当前程序状态寄存器（CPSR）。在Pwn中，重点关注函数参数（R0-R3）、栈指针（SP）、链接寄存器（LR）和程序计数器（PC）。

寄存器编号 助记符 / 别名 主要用途 在函数调用中的角色
R0 - R3 a1 - a4 函数参数 / 返回值 传递前四个参数给被调用函数。R0通常存放函数返回值。
R4 - R11 v1 - v8 局部变量寄存器 被调用者保存（函数结束后必须恢复原值）。
R12 IP 内部过程调用寄存器 链接器临时使用，调用者保存。
R13 SP 栈指针 (Stack Pointer) 指向当前栈顶。与x86不同，ARM通常不需要专门的EBP/RBP。
R14 LR 链接寄存器 (Link Reg) 存放函数跳转后的返回地址（BL指令使用）。
R15 PC 程序计数器 (Program Counter) 类似于x86的EIP/RIP，指向当前正在取指的指令地址。

指令

ARM指令集存在一些特性：

  1. 指令集切换（ARM vs Thumb）：ARM状态下指令固定4字节，Thumb状态下指令为2或4字节。跳转时，目标地址的最低位（LSB）若为1，CPU会切换到Thumb模式执行；若为0，则是ARM模式。
  2. 多寄存器存取：ARM非常擅长通过一条指令操作多个寄存器和栈（如 PUSH 和 POP）。

Plaintext

特性

叶子函数与非叶子函数

和MIPS类似，ARM在处理函数调用返回时也有叶子和非叶子的区分。

叶子函数：函数中不调用其他函数。 叶子函数不会修改 LR 寄存器的值。因此在函数结尾，它不需要访问栈上的返回地址，直接使用 BX LR 就可以返回调用处。

代码段

非叶子函数：函数中调用了其他函数。 由于非叶子函数（比如你的漏洞函数里调用了 gets 或 printf）在调用子函数时，会执行 BL 指令，这会覆盖掉它原本的 LR 值。因此，非叶子函数在开始时必须将 LR 压入栈中保存。

代码段

所以：在ARM架构下，最经典的栈溢出就是覆盖非叶子函数在栈上保存的 LR。当函数执行到 POP {..., PC} 时，被你覆盖的恶意地址就会直接加载进 PC（程序计数器），从而劫持控制流。
