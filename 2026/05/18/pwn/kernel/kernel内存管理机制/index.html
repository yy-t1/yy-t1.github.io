kernel内存管理机制

物理内存（RAM）

内核并不把物理内存简单看作一整块单一空间，而是将其划分为三级：

  1. 节点 (Nodes - pg_data_t)
  2. 区域 (Zones - struct zone)
  3. 页 (Pages - struct page)

节点

一组 CPU 本地访问最快的那片物理内存。

现代服务器通常都是NUMA（Non-Uniform Memory Access，非一致性内存访问） 架构。（每个 CPU 插槽（Socket）都有自己直连的物理内存条）

即：

CPU访问“离自己近”的内存更快

CPU访问“其他CPU附近”的内存更慢

为了管理这种物理差异，内核引入了“节点（Node）”的概念。每一个具有独立内存控制器（CPU）的内存簇，就是一个 Node。

区域

具有相同访问限制的物理内存区域。

由于很多硬件不能访问全部的物理内存（例如：某些设备无法访问高地址的物理内存，一旦访问就会崩溃），所以内核就将一个Node划分成不同的区域

页

物理内存管理最小单位（4KB），每个物理页都有struct page用来存储页的信息。

虚拟内存

在程序实际使用中，使用的其实是虚拟内存，而内核负责将其映射到物理内存。

（安全隔离与对物理地址的碎片化利用）

虚拟空间也被分为两部分：

  • 用户空间：每个进程都有自己独立的用户空间。
  • 内核空间： 所有进程共享同一个内核空间。

将虚拟地址转化为内存地址就需要依靠一下页表和内存管理单元。

页表 (Page Table)

内核维护的一张地址映射表。

记录了进程的每一个虚拟页（Virtual Page）到底指向哪个真实的物理页框（Physical Frame）。

MMU (内存管理单元)

CPU里的硬件翻译器

负责根据也页表实时将虚拟地址翻译成物理地址。

内存映射

当进程请求内存（如：malloc），只是在虚拟空间分配一块区域（VMA），并不会立刻分配物理内存地址，只有进程真正读写这块内存触发缺页中断（Page Fault），才会真正区物理内存寻找空闲页并建立映射关系。

缺页中断：CPU 访问了一个当前无法直接使用的虚拟地址使得CPU陷入内核态让内核来处理。

物理内存分配机制

伙伴系统 (Buddy System)

将物理内存划分为1页、2页、4页、8页…直到1024页的连续内存块（即$2^n$的阶数）。

分配：如果当前大小的块用尽，则会将大一阶的块分成两个“伙伴”。

释放：如果两个相邻的“伙伴”空闲，则会将其合并成更大的块。

Slub 分配器

由于Buddy System最小单位是4KB Page，但是多数请求是以字节为单位的。

如果一直以Page为单位来分配，那么就会造成很多浪费。

SLUB分配器则负责把 Buddy System 分配来的 Page（页），切分成固定大小的 Object（对象）

空闲列表

释放的 object会进入freelist，待下一次kmalloc时会优先成freelist拿对象。
