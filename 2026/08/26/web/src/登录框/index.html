登录框

1.弱口令

毋庸置疑

FOFA语法：

搜索默认账号密码，测试密码，弱口令，厂商名称

（先手测几个试试，没有限制再爆破）

（如果有 IP 频率限制，可以尝试在 HTTP 头中添加 X-Forwarded-For 伪造 IP；如果有简单的验证码，可以尝试复用验证码或删除验证码参数来绕过）

2.万能密码

利用 SQL 语句的逻辑判断缺陷，构造恒为“真”的条件来绕过密码验证。

3.返回包篡改

通过修改返回包中的状态码或结果字段，让前端认为登录请求已成功。

1.修改状态码：将表示失败的 400 或 401 等状态码，改为表示成功的 200

2.修改结果字段：将 fail、false 等表示失败的关键词，替换为 true、success 等表示成功的关键词

（使用登录成功的返回包给登录失败的）

4.sql注入

  • 报错注入：在用户名后加单引号 '，看页面是否报错。
  • 盲注：输入 admin' and sleep(5)#，如果页面加载明显变慢（转圈5秒），说明数据库执行了延时指令，漏洞存在。

5.XSS(跨站脚本攻击)

可能存在位置：

  1. 账号密码输入框：输入的恶意脚本会被直接执行
  2. URL 参数：登录页面的 URL 中某个参数存在注入点

6. SSRF (服务端请求伪造)

URL：服务器会根据用户提供的 URL 发起请求，若该 URL 可控，攻击者就可以构造恶意地址，让服务器访问内部资源或外部恶意服务。

常见的测试入口包括：

  • 登录页面中远程加载的图片资源
  • URL 中包含的链接跳转参数

7.URL跳转

登录成功后，系统通常会跳转回之前的页面，这个跳转地址往往由 URL 参数控制（如 returnUrl）。

检测思路：和SSRF很想，测试SSRF的时候可以顺手测了。将 URL 参数修改为恶意的钓鱼网站地址（如 http://evil.com）。如果登录后直接跳转到了该网址，即存在跳转漏洞，常被用于钓鱼攻击。

8.用户名枚举

系统对“账号不存在”和“密码错误”给出了不同的提示，或者响应时间有明显差异。

这会导致攻击者可以先筛选出所有存在的账号，再进行定向爆破

（分别输入一个不存在的账号和一个存在的账号，对比页面的提示文字或接口返回的错误代码是否不同。）

9.目录扫描

登录页周围可能遗留了敏感文件，如源代码备份、接口文档或 Git 配置信息。

10.隐藏注册接口

前端未显示注册按钮，但后端接口存在,本来只有登录口，没有注册功能。

尝试访问 /register, /user/reg, /api/signup 等常见路径

（我的第一个漏洞就是利用隐藏的注册接口登录上去，然后再水平越权找到的敏感信息）

11.密码修改接口

1.修改密码时通过抓包改ID

2.接口可能存在缺陷，不传旧密码会默认为管理员跳过检验（抓包修改）

3.隐藏的重置密码接口

  • /api/user/reset_password
  • /api/admin/change_pwd
  • /user/update?action=password

向这些发送POST请求带上 user_id=admin&new_pass=123456，如果无鉴权可能可以直接更改

12.JS中提取接口

前端JavaScript文件可能存在隐藏的接口信息

  1. 未授权访问：直接拼接后端接口路径，绕过前端UI限制，测试越权或未授权漏洞。
  2. 敏感信息泄露：发现硬编码的AK/SK、测试环境IP、内网域名等。
  3. 隐藏功能点：发现废弃但未下线的旧版本接口（通常缺乏安全校验）。

13.验证码

  1. 验证码复用
  2. 验证码置空（抓包删除其参数值或直接删除整个参数）
  3. 只在前端用 JS 判断验证码是否正确，后端完全不校验。
  4. 未限制生成频率，攻击者高频请求验证码接口，会导致服务器资源耗尽。

（找到验证码图片的 URL（如 /code.php?t=123）发送到 Intruder，设置高并发线程（如 50-100 线程）无限请求，观察响应是否变慢，CPU是否飙升）

14.手机号验证码漏洞

  1. 短信轰炸（批量多次发送）
  2. 验证码直接返回在HTTP的数据包里
  3. 验证码双发/并发绕过
  4. 验证码爆破
  5. 测试验证码未删除

15.其他端口

○ 8080 / 8081 / 9090：常见于 Tomcat、JBoss 或开发测试环境 Web 服务。
○ 7001 / 7002：WebLogic 控制台（常存在反序列化漏洞）。
○ 8888：宝塔面板或其他运维管理后台。
○ 6379：Redis 数据库（检查未授权访问）。
○ 27017：MongoDB 数据库（检查未授权访问）。

16.指纹识别与框架漏洞（？）

识别处底层的开发框架（如 Spring Boot, Shiro, Struts2）或中间件（WebLogic, JBoss）

利用历史上已知的公开CVE

17.任意注册或注册覆盖

注册时抓包改手机号

重新注册看看是否覆盖新密码
