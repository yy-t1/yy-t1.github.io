文件上传漏洞

简介

文件上传漏洞：Web 应用允许用户上传文件，但没有对文件类型、内容、路径做严格校验，导致攻击者能上传 WebShell、恶意脚本，最终拿到服务器权限。

挖掘方法

显性上传点：查找可用于上传文件的接口

隐性上传点：

  1. 文本编辑器内置的图片/文件上传
  2. API接口
  3. 移动端API
  4. 第三方组件上传接口

测试方法：

  • 先上传正常图片查看返回包
  • 上传脚本文件查看结果
  • 分析过滤机制
  • 构造绕过

前后端判断

前端

特征：

  • 上传非法文件时，页面直接弹窗提示，请求都没发出去
  • 抓包发现无HTTP请求或请求但返回内容与前端显示一致

方法：

  • 浏览器禁用javascript
  • 自己构造请求包

后端

特征：

  • 请求发出去了，服务器返回了错误响应
  • 常见响应：HTTP 200 + JSON {"code": 400, "msg": "文件类型不允许"}
  • 或 HTTP 403/415 等错误状态码

二次渲染绕过

原理： 后端对上传的图片进行二次处理（缩放、裁剪、格式转换），处理过程中会重写图片数据，导致嵌入的恶意代码被清除。但我们可以找到渲染后不变的区域，把代码藏在里面。

GIF 二次渲染绕过：

  1. 上传一个正常的 GIF 图片
  2. 下载服务器处理后的 GIF 图片
  3. 用 hex 编辑器（如 HxD / 010 Editor）对比原图和渲染后的图
  4. 找到渲染后保持不变的字节区域（通常是 GIF 文件头和部分数据区）
  5. 在不变的区域中插入 PHP 代码
  6. 重新上传

PNG 二次渲染绕过：

PNG 的渲染比 GIF 复杂，因为 PNG 使用了 IDAT 块存储压缩数据。绕过思路有两种：

方法一：写入 PLTE 块（索引色模式）

方法二：构造 IDAT 块

JPG 二次渲染绕过：

JPG 使用有损压缩，渲染后大部分数据都会变化，但可以：

  1. 上传 → 下载渲染后的图片
  2. 对比找到不变区域
  3. 在不变区域注入代码
  4. JPG 绕过难度最大，建议优先尝试 GIF 和 PNG
EXIF注入

原理：利用图片的 EXIF 元数据字段注入 PHP 代码。某些场景下，后端程序会使用 exif_read_data() 等函数读取 EXIF 信息，如果直接输出未过滤，可能导致代码执行。

4.配置文件注入

核心：不上传脚本文件，而是上传服务器的配置文件，通过修改配置让服务器把普通文件当脚本解析。

.htaccess（Apache）

原理：Apache 支持 .htaccess 文件做目录级配置。如果上传目录允许 .htaccess 生效（AllowOverride 不是 None），就可以通过上传 .htaccess 文件来改变该目录的解析规则。

注意事项：

  • 有些上传接口会过滤 .htaccess 这个文件名，可以尝试 .htaccess.、.htaccess%20
  • 需要 Apache 的 AllowOverride 配置允许 .htaccess 覆盖
  • 如果服务器用的是 Nginx，.htaccess 完全没用
.user.ini（Nginx + PHP-FPM）

原理：PHP 支持用户自定义的 php.ini 文件（.user.ini），作用范围是当前目录及其子目录。只要 PHP 以 CGI/FPM 模式运行（而不是 Apache 模块），这个文件就会生效。

1.上传 .user.ini 文件，内容为：

auto_prepend_file=shell.jpg

2.上传 shell.jpg，内容为 PHP 一句话：

<?php eval($_POST["cmd"]);?>

3.在同一目录下找到一个已有的 PHP 文件（或者自己上传一个正常的 PHP 文件），访问它

4.访问该 PHP 文件时，auto_prepend_file 会自动包含 shell.jpg，代码被执行

user.ini 的生效时间：

  • .user.ini 有一个缓存时间，由 user_ini.cache_ttl 控制，默认 300 秒（5 分钟）
  • 也就是说上传后可能要等几分钟才生效，不要以为没成功就放弃
web.config（IIS）

原理：IIS 使用 web.config 做 XML 格式的配置文件，功能类似 .htaccess
