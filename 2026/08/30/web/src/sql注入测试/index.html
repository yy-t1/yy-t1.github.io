sql注入测试

简介

现状

  1. 常规扫描器（如AWVS、AppScan）的自动Payload（如 AND 1=1）极易被拦截或封禁IP 。（WAF）
  2. 某些老新网站还是存在大量注入
  3. src测试需要严格留意边界，获取database()（库名）或 user()（当前用户）即可，严禁获取个人信息以及在 DELETE / UPDATE / INSERT 业务点使用扫描器

在 增加、删除、修改（Update/Insert/Delete）的功能点，绝对禁止使用 SQLMap 自动扫描！！！

分类

1.按数据类型：

  • 整型 (Integer)：select * from users where id = 1。参数直接参与运算，无需闭合引号 。

  • 字符型 (String)：select * from users where id = '1'。参数被引号包裹，占比最高，必须先闭合引号才能执行后续语句 。

2.按位置：

  • 常规：GET/POST 参数。

  • JSON注入：常见于API接口，需注意JSON格式破坏问题 。

  • 排序注入 (Order By)：重难点。出现在 ORDER BY 后面。因为 ORDER BY 后的参数如果是字符串（如 '1'）会导致排序功能失效，所以开发人员往往无法使用预编译（Prepare Statement），只能直接拼接，导致必然存在注入风险 。

常规注入手法

1.整数型

原理：数据库会将数学运算结果作为参数值执行。WAF通常只拦截SQL关键字，不拦截数字运算。

2.字符型

原理：利用 SQL 语法的引号配对规则。此方法不使用 AND、OR 等敏感词，误报率极低且能绕过绝大多数 WAF 。

3.注释符号

4.Order By排序注入

预编译机制：预编译将参数视为“值”而非“代码”。

（所以使用Order By时必须使用拼接，从而导致注入）

5. JSON / Int类型
